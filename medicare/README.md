# MediCare Spring Boot Backend (Java 17/21 LTS)

Enterprise healthcare backend ported faithfully from the original ASP.NET Core MediCare backend.

---

## 📋 Architectural Highlights

- **Platform:** Java 17 LTS (compatible with Java 21 LTS), Spring Boot 3.3.4
- **ORM & Data:** Spring Data JPA + Hibernate with `PhysicalNamingStrategyStandardImpl` to map PascalCase tables (`Users`, `Medicines`, `MedicineSchedules`, `MedicineLogs`, `Patients`, `Caregivers`, `CaregiverPatients`, `Notifications`, `EmergencyAlerts`, `EmailDeliveryLogs`) without altering EF Core MySQL database schemas.
- **Safety Policy:** `spring.jpa.hibernate.ddl-auto=validate` to strictly prevent destructive DDL updates on existing tables.
- **Security & Cross-Framework Compatibility:**
  - Custom `AspNetIdentityPasswordEncoder` supporting ASP.NET Core Identity Version 3 PBKDF2-HMAC-SHA256 (10,000 iterations, 128-bit salt, 256-bit subkey, `0x01` binary marker) with automatic fallback for BCrypt.
  - JJWT (0.12.5) token provider supporting both standard RFC 7519 JWT claims (`sub`, `roles`, `email`, `userId`) and ASP.NET Core WS-Federation URI claims (`http://schemas.xmlsoap.org/ws/2005/05/identity/claims/nameidentifier`, `.../claims/role`, `.../claims/emailaddress`).
- **Idempotent Background Reminders:**
  - Scheduled background service (`@Scheduled(fixedRate = 15000)`) checking upcoming (-2 min), missed (+5 min), and caregiver escalation (+30 min) medicine doses.
  - Uses the `EmailDeliveryLogs` table to record and guarantee zero duplicate reminder emails across restarts or concurrent execution.
  - Can be toggled on/off via `medicare.reminder.enabled=true|false`.
- **Dual Case Endpoint Support:**
  - Controllers map both lowercase (`/api/auth/login`, `/api/medicine`) and PascalCase (`/api/Auth/Login`, `/api/Medicine`) routes for 100% compatibility with any frontend client.

## ⚙️ Environment Variables & Configuration

The application is configured in `src/main/resources/application.properties` with fallback defaults. You can override any setting using environment variables:

| Variable | Description | Default Value |
|---|---|---|
| `SERVER_PORT` | HTTP port for the Java backend | `8080` |
| `DB_URL` | MySQL JDBC connection string | `jdbc:mysql://localhost:3306/medicare_db?useSSL=false&serverTimezone=UTC&allowPublicKeyRetrieval=true` |
| `DB_USERNAME` | MySQL database user | `root` |
| `DB_PASSWORD` | MySQL database password | `password` |
| `JWT_KEY` | Secret key for HMAC-SHA256 JWT tokens | `YourSuperSecretKeyForJwtTokenGenerationMustBeLongEnough123!` |
| `JWT_ISSUER` | JWT Issuer claim | `MediCareApi` |
| `JWT_AUDIENCE` | JWT Audience claim | `MediCareClient` |
| `EMAIL_SENDER_EMAIL` | SMTP sender email address | `noreply@medicare.com` |
| `EMAIL_SENDER_NAME` | Display name for emails | `MediCare Notifications` |
| `EMAIL_PASSWORD` | SMTP password / app password | (empty) |
| `EMAIL_HOST` | SMTP server host | `smtp.gmail.com` |
| `EMAIL_PORT` | SMTP server port | `587` |
| `MEDICARE_REMINDER_ENABLED` | Background reminder service toggle | `true` |
| `MEDICARE_REMINDER_INTERVAL_MS` | Background reminder poll interval (ms) | `15000` |

## 🚀 Running Both Backends Side-by-Side

### 1. Java Backend (Folder 1 — Port 8080)

From `C:\Users\Dell\OneDrive\Desktop\Medicare in java\medicare`:

```powershell
# Run with Maven Wrapper
.\mvnw.cmd spring-boot:run

# Or run the packaged jar
java -jar target/medicare-0.0.1-SNAPSHOT.jar
```

To run with custom database credentials:
```powershell
$env:DB_USERNAME="root"
$env:DB_PASSWORD="your_mysql_password"
$env:DB_URL="jdbc:mysql://localhost:3306/medicare_db?useSSL=false&serverTimezone=UTC&allowPublicKeyRetrieval=true"
java -jar target/medicare-0.0.1-SNAPSHOT.jar
```

### 2. .NET Backend (Folder 2 — Port 5000 / 7000 / IIS)

From `C:\Users\Dell\OneDrive\Desktop\MediCare`:

```powershell
dotnet run
```

> **Note:** The Java backend is intentionally bound to port `8080` and the .NET backend is bound to ports `5000` / `7000` or IIS Express. They can execute simultaneously against the same MySQL database safely because:
> 1. Entity mappings in Java strictly validate the schema without modifying it (`ddl-auto=validate`).
> 2. Password hashes generated by either system can be verified by both systems.
> 3. To avoid dual email dispatch when both are active, set `MEDICARE_REMINDER_ENABLED=false` on one backend.

## 📡 API Endpoints Reference

All endpoints support both `/api/<resource>` and `/api/<Resource>` casings.

### 1. Authentication (`/api/auth`)
| Method | Endpoint | Description | Role / Auth |
|---|---|---|---|
| `POST` | `/api/auth/register` | Register new user (Patient, Caregiver, Admin) | Public |
| `POST` | `/api/auth/login` | Authenticate and obtain JWT token | Public |

### 2. Medicine Management (`/api/medicine`)
| Method | Endpoint | Description | Role / Auth |
|---|---|---|---|
| `GET` | `/api/medicine` | List all medicines for user (or patient for caregiver) | Authenticated |
| `GET` | `/api/medicine/{id}` | Get medicine details | Authenticated |
| `POST` | `/api/medicine` | Add new medicine | Patient / Caregiver |
| `PUT` | `/api/medicine/{id}` | Update medicine details | Patient / Caregiver |
| `DELETE` | `/api/medicine/{id}` | Delete medicine | Patient / Caregiver |

### 3. Medicine Schedules (`/api/medicineschedule`)
| Method | Endpoint | Description | Role / Auth |
|---|---|---|---|
| `GET` | `/api/medicineschedule` | Get schedules (optionally filter by `medicineId`) | Authenticated |
| `POST` | `/api/medicineschedule` | Create schedule for a medicine | Patient / Caregiver |
| `PUT` | `/api/medicineschedule/{id}` | Update schedule | Patient / Caregiver |
| `DELETE` | `/api/medicineschedule/{id}` | Delete schedule | Patient / Caregiver |

### 4. Medicine Logs (`/api/medicinelog`)
| Method | Endpoint | Description | Role / Auth |
|---|---|---|---|
| `GET` | `/api/medicinelog` | Get medicine intake logs (by `patientId` / `medicineId`) | Authenticated |
| `POST` | `/api/medicinelog` | Create medicine log | Authenticated |
| `POST` | `/api/medicinelog/mark-as-taken/{id}` | Mark dose as Taken (decrements stock & triggers low-stock alerts) | Authenticated |

### 5. Caregiver-Patient Links (`/api/caregiverpatient`)
| Method | Endpoint | Description | Role / Auth |
|---|---|---|---|
| `GET` | `/api/caregiverpatient/my-patients` | Caregiver's assigned patients | Caregiver |
| `GET` | `/api/caregiverpatient/my-caregivers` | Patient's assigned caregivers | Patient |
| `POST` | `/api/caregiverpatient/link` | Link caregiver and patient | Caregiver / Patient |
| `POST` | `/api/caregiverpatient/unlink` | Remove link | Caregiver / Patient |

### 6. Emergency Alerts (`/api/emergency`)
| Method | Endpoint | Description | Role / Auth |
|---|---|---|---|
| `POST` | `/api/emergency/trigger` | Trigger SOS alert (notifies caregivers via in-app & email) | Patient |
| `GET` | `/api/emergency/patient/{patientId}` | Get emergency alerts history for patient | Authenticated |
| `PUT` | `/api/emergency/resolve/{id}` | Mark alert as resolved | Caregiver / Admin |

### 7. In-App Notifications (`/api/notification`)
| Method | Endpoint | Description | Role / Auth |
|---|---|---|---|
| `GET` | `/api/notification` | Fetch notifications for current user | Authenticated |
| `PUT` | `/api/notification/{id}/read` | Mark single notification as read | Authenticated |
| `PUT` | `/api/notification/read-all` | Mark all notifications as read | Authenticated |

### 8. Dashboards & Analytics
| Method | Endpoint | Description | Role / Auth |
|---|---|---|---|
| `GET` | `/api/adherence/patient/{patientId}` | Calculate patient medication adherence % | Authenticated |
| `GET` | `/api/patientdashboard` | Full patient dashboard metrics & daily schedule | Patient |
| `GET` | `/api/caregiverdashboard` | Caregiver dashboard metrics & linked patients | Caregiver |
| `GET` | `/api/admindashboard` | System-wide statistics (users, logs, alerts) | Admin |
